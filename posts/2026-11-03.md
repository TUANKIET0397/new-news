# Tech Radar 03/11/2026: Next.js sắp có bản vá bảo mật, Redis vá lỗi cluster bus, PostgreSQL 19 vào RC
> Hôm nay có ba thứ nên để mắt: Next.js 16.4.4 ra kèm thông báo sẽ có security release vào ngày mai, Redis vá lỗi heap overflow ở cluster bus, và PostgreSQL 19 đã ở giai đoạn release candidate với ngày GA dự kiến 19/11. Ai chạy Next.js trên production, Redis Cluster hoặc đang lên kế hoạch nâng PostgreSQL nên đọc phần Điểm nóng.

## Điểm nóng hôm nay

### Next.js 16.4.4: bản backport, và security release được báo trước cho ngày mai
Ngày 02/11, Next.js phát hành v16.4.4 (tag Latest), một bản backport bug fix. Điểm đáng chú ý nhất nằm trong release notes: có một "announced security release" cho tháng 11 sẽ được công bố vào ngày hôm sau, kèm link tới bài viết trên blog Next.js. Mình không truy cập được nextjs.org từ môi trường này nên chưa biết nội dung lỗ hổng, mức độ hay phiên bản bị ảnh hưởng.

Các thay đổi khác trong 16.4.4: Turbopack reload trang khi bỏ lỡ cập nhật CSS lúc khởi động, revert một tối ưu "strict module factory chunk", phát shared-runtime bootstrap của Turbopack trong PPR resume để nhận CSP nonce, và chuyển từ `jsonwebtoken` sang `fast-jwt` (PR #100885). Release notes không nói lý do hay khác biệt về hành vi của `fast-jwt`.

Áp dụng: nếu bạn tự verify JWT trong code của Next.js (middleware, route handler), đọc PR #100885 trước khi nâng. Và theo dõi trang blog Next.js trong ngày để biết phiên bản vá, vì security release thường cần nâng gấp.

Nguồn: [Next.js v16.4.4](https://github.com/vercel/next.js/releases/tag/v16.4.4), [Next.js releases](https://github.com/vercel/next.js/releases)

### Redis 8.10.3 và 8.8.4: vá heap buffer overflow ở cluster bus
Ngày 26/10, Redis phát hành 8.10.3 và 8.8.4, cả hai đánh dấu urgency SECURITY và chỉ chứa một fix: heap buffer overflow khi propagate message `PUBLISH` hoặc `SPUBLISH` lớn hơn 4GB qua cluster bus ở chế độ cluster. Release notes không gán CVE ID trong phần mình đọc.

Ngoài ra, Redis 8.12 đã có RC1 (29/10) và RC2 (01/11). RC1 giới thiệu compressed bitmap (tích hợp redis-roaring vào core), các lệnh mới `BITRANGEINTARRAY`, `BLESS`, nhóm lệnh expire theo từng member của set (`SEXPIRE`, `STTL`), và `CLUSTER MIGRATION STATUS` báo tiến độ migrate slot. Về bảo mật, RediSearch đã dùng hash chống collision cho giá trị được index, và không còn đọc ngoài biên với ký tự UTF-8 dở dang. Redis ghi rõ pre-release không phù hợp cho production.

Áp dụng: nếu bạn chạy Redis Cluster (cache hoặc queue cho NestJS với BullMQ, Laravel Horizon), nâng lên bản patch của nhánh đang dùng. Nếu không dùng cluster thì rủi ro thấp hơn, nhưng patch vẫn nên theo lịch bảo trì.

Nguồn: [Redis releases](https://github.com/redis/redis/releases)

### PostgreSQL 19 RC1: GA dự kiến 19/11/2026
PostgreSQL 19 RC1 ra ngày 15/10. Theo thông báo, RC2 dự kiến 12/11 và GA dự kiến 19/11 nếu không phát sinh vấn đề. Mình không truy cập được postgresql.org để đọc trực tiếp, nên các điểm dưới đây lấy từ kết quả tìm kiếm trích thông báo beta/RC chính thức, hãy đối chiếu lại release notes trước khi quyết định nâng:

- `REPACK` với tùy chọn `CONCURRENTLY` để rebuild bảng ít khóa hơn.
- `GROUP BY ALL`.
- `WAIT FOR LSN` cho pattern read-your-writes trên replica.
- Logical replication đồng bộ giá trị sequence, giúp upgrade online dễ hơn.
- JIT tắt mặc định, `default_toast_compression` mặc định `lz4`.
- Nâng cấp từ bản cũ phải dùng `pg_upgrade` hoặc `pg_dump`/`pg_restore`.

Áp dụng: thay đổi mặc định của JIT và TOAST compression có thể làm query plan và kích thước bảng khác đi. Nếu bạn muốn thử, dựng một instance 19 RC trong Docker, restore bản dump staging và so `EXPLAIN ANALYZE` của vài query nặng, đừng nâng thẳng production khi mới GA.

Nguồn: [PostgreSQL 19 RC 1 released](https://www.postgresql.org/about/news/postgresql-19-rc-1-released-3409/)

### Nhắc lại: Node.js 22.23.4 / 24.22.1 / 26.12.1 vẫn là việc chưa xong của nhiều team
Bản vá ngày 21/10 (đã nhắc trong bản tin 01/11) xử lý 10 lỗ hổng, 4 mức High. Chi tiết theo trang chính thức: CVE-2026-111497 là out-of-bounds write trong Brotli decoder đi kèm, có thể dẫn tới crash, lộ bộ nhớ hoặc RCE trên input độc hại; CVE-2026-105482, CVE-2026-105483, CVE-2026-106069 liên quan tới việc kiểm tra hostname/IP (NUL byte trong `dns.resolve*()`, IP dùng chữ số fullwidth, IPv4 có số 0 đứng đầu bị hiểu là octal) khiến kiểm tra certificate có thể sai. Node.js 20 đã EOL và không có bản vá.

Áp dụng: kiểm tra `node -v` trên VPS và base image Docker (`node:22`, `node:24`), rebuild image nếu tag đang pin ở bản cũ.

Nguồn: [Node.js October 2026 Security Releases](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)

## Cài đặt và dùng thử

### Scrapling: framework scraping cho Python
Đang ở hạng 3 GitHub Trending hôm nay. Scrapling gộp HTTP request, browser, parser và crawl đồng thời trong một thư viện, có cả CLI, MCP server và Agent Skill cho AI agent. License BSD-3-Clause, yêu cầu Python 3.10 trở lên.

```bash
pip install "scrapling[fetchers]"
scrapling install
```

```python
from scrapling.fetchers import Fetcher

page = Fetcher.get('https://quotes.toscrape.com/')
quotes = page.css('.quote .text::text').getall()
print(quotes)
```

Dùng cho script lấy dữ liệu trong service FastAPI hoặc job nền. Hãy tôn trọng `robots.txt` và điều khoản của site đích.

### agent-desktop: CLI để agent điều khiển ứng dụng desktop
Đứng đầu GitHub Trending hôm nay (vercel-labs). Đây là CLI computer-use chạy trên macOS, Windows, Linux, đọc accessibility tree của OS và trả JSON, mỗi phần tử tương tác có một ref để agent thao tác thay vì khớp theo pixel. License Apache-2.0. Trên macOS cần cấp quyền Accessibility, Linux cần phiên đồ họa và `at-spi2-core`.

```bash
npm install -g agent-desktop
agent-desktop version
agent-desktop snapshot --app Finder -i
```

Lưu ý từ README: snapshot, clipboard, screenshot có thể chứa nội dung riêng tư, đừng đẩy lên log công khai. Ref gắn với từng snapshot, ref cũ phải được thay bằng snapshot mới.

## Góc học sâu

### Giới hạn kích thước message và lý do bug "4GB" hay lặp lại
Lỗi của Redis có dạng quen thuộc: một trường độ dài vượt ngưỡng mà code không nghĩ tới (message lớn hơn 4GB, tức vượt số nguyên 32 bit không dấu) khiến phép tính kích thước buffer sai và ghi tràn. Cùng họ với lỗi Brotli của Node.js (ghi ngoài biên khi input méo) và các giới hạn mặc định mới của NestJS 12.2 mà bản tin hôm qua nhắc tới.

Bài học thực dụng cho backend: mọi đường nhận dữ liệu từ ngoài đều cần ba chặn trên, kích thước tối đa mỗi message, độ sâu/độ lặp tối đa, và thời gian xử lý tối đa. Ở tầng ứng dụng, đặt `client_max_body_size` trong Nginx, giới hạn payload trong body parser, và giới hạn kích thước message khi publish lên Redis hoặc queue. Nếu một message thật sự cần vài trăm MB, đừng nhét qua pub/sub; lưu object vào storage và chỉ gửi ID.

## Tối ưu dùng AI

### Chủ đề hôm nay: prompt để debug với AI, đưa log, repro và giả thuyết
Prompt "code bị lỗi, sửa giúp" khiến agent phải đoán. Debug hiệu quả với AI cần ba thứ mà bạn đang có sẵn và agent thì không: lỗi nguyên văn, cách tái hiện, và những gì bạn đã loại trừ. Theo hướng dẫn của Anthropic, cho model tiêu chí thành công kiểm tra được (test, lệnh chạy) là điều quan trọng nhất, vì khi đó nó tự xác minh được bản sửa.

Quy trình:

1. Chạy lại lỗi và copy nguyên văn stack trace hoặc log, không diễn đạt lại.
2. Ghi lệnh tái hiện tối thiểu (request curl, test fail, bước click).
3. Liệt kê giả thuyết đã thử và kết quả, để agent không lặp lại.
4. Yêu cầu chẩn đoán trước khi sửa, rồi viết một test fail trước bản sửa.

Template:

```
<error>
[dán nguyên văn stack trace / log, kèm timestamp nếu có]
</error>

<repro>
Chạy: curl -X POST localhost:3000/orders -d '{"items":[]}'
Kỳ vọng: 400. Thực tế: 500.
</repro>

<already_tried>
- Đã thêm @IsNotEmpty() cho items: không đổi.
- Lỗi không xảy ra khi items có 1 phần tử.
</already_tried>

<task>
Tìm nguyên nhân gốc, chưa sửa vội. Nêu 2-3 giả thuyết xếp theo khả năng và cách kiểm tra từng cái.
Sau khi mình chọn, viết một test fail tái hiện lỗi, rồi mới sửa tới khi test pass và npm run test xanh.
</task>
```

Vài lưu ý: đừng dán cả repo, chỉ file nằm trên đường đi của lỗi; che secret và dữ liệu khách hàng trong log trước khi dán; nếu agent đề xuất bọc try/catch để "hết lỗi", hỏi lại nguyên nhân gốc là gì.

### Áp dụng ngay hôm nay
Lần tới gặp một lỗi thật trong dự án, viết đủ bốn khối `<error>`, `<repro>`, `<already_tried>`, `<task>` trước khi hỏi AI, và yêu cầu nó viết test fail trước khi sửa. Sau đó so với cách bạn hay hỏi (một câu ngắn) xem số vòng trao đổi giảm bao nhiêu. Lưu template vào snippet để dùng lại.
