# Tech Radar 10/11/2026: Claude Fable 5.2 ra mắt, Claude Code 2.1.321 vá lỗi lộ token MCP OAuth, mai Node.js phát hành bản vá
> Hôm nay đáng chú ý nhất là Anthropic phát hành Claude Fable 5.2 (09/11) và bản Claude Code 2.1.321 kèm hai bản sửa lỗi bảo mật. Node.js sẽ phát hành bản vá mức High cho 22.x, 24.x và 26.x vào ngày mai 11/11. Ai gọi Claude API từ backend, dùng Claude Code hoặc chạy Node.js trên VPS nên đọc hết.

## Điểm nóng hôm nay

### Claude Fable 5.2 và Mythos 5.2 ra mắt ngày 09/11
Theo trang models của Claude docs, Fable 5.2 (`claude-fable-5-2`) phát hành ngày 09/11/2026, nhắm vào reasoning khó và công việc agent chạy dài nhiều giờ. Thông số: context 1M token, output tối đa 128K, giá $8 / $40 mỗi triệu token (input / output), thinking dạng adaptive luôn bật, effort mặc định `high`. Giá đọc từ prompt cache là $0.20 mỗi triệu token, còn Batch API giảm 50%. Mythos 5.2 có cùng năng lực nhưng chỉ mở cho tổ chức đã qua chương trình xác minh của Anthropic (ví dụ Cyber Verification Program).

Có vài điểm gây lỗi khi nâng cấp, theo trang model: forced tool use (`tool_choice` loại `any` hoặc `tool`) trả về lỗi 400, không được gửi `temperature`, `top_p`, `top_k`, và model yêu cầu lưu dữ liệu 30 ngày (không dùng được với zero data retention nếu Anthropic không cho phép riêng). Tài liệu cũng cảnh báo chi tiết khi bạn đổi `system`, `tools` hoặc các message cũ giữa hội thoại, hoặc chuyển hội thoại giữa các model; phần này nằm ở trang breaking changes của Fable 5.2 mà mình chưa đọc hết, nên hãy đọc trước khi đổi.

Áp dụng: docs chính thức vẫn khuyên bắt đầu với Opus 5.5 cho phần lớn workload, và chỉ chuyển sang Fable 5.2 khi eval của bạn ở effort `xhigh` hoặc `max` vẫn chưa đạt. Với giá gấp đôi Opus 5.5, đây là model dành cho tác vụ khó, không phải mặc định cho mọi endpoint. Mình chưa đọc bài announcement và system card nên không ghi số benchmark.

Nguồn: [Claude Fable 5.2 (Claude docs)](https://platform.claude.com/docs/en/models/fable-5-2/overview), [Models overview](https://platform.claude.com/docs/en/models/overview), [Anthropic News](https://www.anthropic.com/news)

### Claude Code 2.1.321: Fable 5.2 làm mặc định, sửa lỗi lộ secret và bypass sandbox
Changelog chính thức bản 2.1.321 (09/11) ghi: Fable 5.2 là model Fable mặc định; lựa chọn Fable 5.1 đã lưu được chuyển sang alias `fable` (muốn quay lại dùng `/model claude-fable-5-1`); thêm `--settings <file>` cho `claude remote-control`; mod do Claude viết không còn tự bật ở chế độ auto và bypass. Hai bản sửa quan trọng: yêu cầu MCP OAuth có thể gửi secret như refresh token sang host khác khi server redirect, và một lệnh Bash chỉ đọc có thể chạy ngoài sandbox mà không hỏi quyền.

Áp dụng: chạy `claude update` (hoặc cách bạn đang dùng để cập nhật), nhất là nếu bạn nối MCP server có OAuth. Chi tiết phần bảo mật ở dưới.

## Góc học sâu

### Redirect và credential: đừng đi theo redirect kèm secret
Lỗi MCP OAuth hôm nay là một lớp lỗi cổ điển của HTTP client: client đi theo redirect sang host khác nhưng vẫn gửi theo thứ chỉ dành cho host ban đầu (header `Authorization`, cookie, refresh token trong body). Server đầu tiên chỉ cần trả `302` sang địa chỉ do kẻ tấn công kiểm soát là lấy được secret.

Quy tắc phòng thủ cho code backend của bạn khi gọi HTTP bên ngoài:
- Khi redirect sang origin khác (khác scheme, host hoặc port), bỏ `Authorization` và cookie. Nhiều thư viện làm sẵn điều này, nhưng hãy kiểm tra thư viện bạn dùng thay vì tin.
- Với token nhạy cảm, tắt tự động follow redirect, tự quyết định và kiểm tra host đích nằm trong allowlist.
- Với webhook hoặc URL do user cung cấp, chặn cả địa chỉ nội bộ (SSRF), vì redirect là cách quen thuộc để vượt kiểm tra ở bước đầu.
- Token ngắn hạn và scope hẹp giảm thiệt hại khi lộ: refresh token không nên đi qua những nơi mà access token đã đủ.

Câu hỏi tự kiểm tra cho service NestJS hay Laravel của bạn: chỗ nào đang gọi URL ngoài với header xác thực, và thư viện HTTP ở đó xử lý redirect cross-origin thế nào?

## Tối ưu dùng AI

### Chủ đề hôm nay: chọn model theo độ khó và chi phí, chỉnh effort trước khi đổi model

Tài liệu "Choosing the right model" của Claude có mấy ý đáng dùng ngay:
- Tuning effort thường là đòn bẩy tốt hơn việc đổi model. Fable 5.2 và Sonnet 5.5 mặc định `high`, Opus 5.5 và Haiku 5.5 mặc định `medium`; bắt đầu từ mặc định rồi chỉnh lên xuống theo eval.
- Hai cách bắt đầu: hiệu quả trước (Haiku 5.5, nâng cấp khi thiếu năng lực) hoặc năng lực trước (Opus 5.5, rồi giảm effort hoặc xuống model rẻ hơn khi workflow đã ổn).
- Chỉ chuyển sang Fable 5.2 khi eval ở effort `xhigh` hoặc `max` của Opus 5.5 vẫn chưa đạt.
- Có thể kết hợp model: executor rẻ leo lên advisor mạnh cho quyết định khó, hoặc orchestrator giao việc nặng cho worker rẻ. Docs có trang "Optimizing for cost and intelligence" cho cả hai chiến lược.
- Quan trọng nhất là có bộ eval riêng cho use case của bạn, test bằng prompt và dữ liệu thật.

Bảng bắt đầu cho một backend hay có AI:

| Tác vụ | Model đề xuất bắt đầu | Giá (input / output mỗi MTok) |
| --- | --- | --- |
| Phân loại, trích xuất, routing số lượng lớn | Haiku 5.5 | từ $0.10 / $0.50 |
| Sinh code, phân tích dữ liệu hằng ngày | Sonnet 5.5 | $2 / $10 |
| Agent code nhiều giờ, refactor lớn | Opus 5.5 | $4 / $20 |
| Reasoning khó, nghiên cứu nhiều bước | Fable 5.2 | $8 / $40 |

Quy trình áp dụng:
1. Chọn 10 đến 20 case thật của endpoint (input và output mong đợi) làm eval.
2. Chạy bằng model rẻ nhất có vẻ đủ, ghi lại tỉ lệ đạt.
3. Chưa đạt thì tăng effort trước, rồi mới lên model cao hơn.
4. Ghi quyết định vào config, không rải chuỗi model ID khắp code.

```ts
// config/ai-models.ts: một nơi duy nhất quyết định model theo loại tác vụ
export const MODELS = {
  classify: 'claude-haiku-5-5',
  codegen: 'claude-sonnet-5-5',
  agent: 'claude-opus-5-5',
  hard: 'claude-fable-5-2',
} as const;

export type Task = keyof typeof MODELS;
export const modelFor = (task: Task) => MODELS[task];
```

Lưu ý khi dùng Opus 5.5 hoặc Fable 5.2: nếu code đang ép `tool_choice` kiểu `any`/`tool` hoặc tắt thinking, docs ghi rằng cần đọc phần breaking changes trước khi đổi.

Nguồn: [Choosing the right model](https://platform.claude.com/docs/en/about-claude/models/choosing-a-model), [Models overview](https://platform.claude.com/docs/en/models/overview)

### Áp dụng ngay hôm nay
Tìm trong code backend của bạn mọi chỗ đang ghi cứng tên model Claude, gom chúng về một file config như ví dụ trên (khoảng 10 phút). Rồi chọn một endpoint và viết 10 case eval ra file, để mai đổi model hay effort còn có thứ để so sánh.
