# Tech Radar 16/11/2026: AG-UI chuẩn hóa luồng event giữa agent và frontend, Vue 3.6 RC15 sửa hàng loạt lỗi computed

> Hôm nay không có bản vá bảo mật hay bản stable lớn nào trong stack chính. Đáng đọc nhất là AG-UI, protocol mã nguồn mở định nghĩa agent stream text, tool call và state xuống frontend qua SSE như thế nào, rất sát với việc bạn đang làm khi viết endpoint chat bằng FastAPI hay NestJS. Ngoài ra Vue 3.6.0-rc.15 sửa hơn chục lỗi reactivity quanh `computed`, Next.js 16.5 canary bật Turbopack GC mặc định, và NVIDIA ra framework đo xem một Agent Skill có thật sự giúp agent làm tốt hơn không.

## Điểm nóng hôm nay

### AG-UI: protocol event cho agent nói chuyện với giao diện người dùng
AG-UI (Agent-User Interaction Protocol) đang lên GitHub Trending. Đây là protocol mở, license MIT, định nghĩa cách một agent backend gửi event xuống frontend trong lúc chạy. README đặt nó cạnh hai chuẩn quen thuộc: MCP cho agent gọi tool, A2A cho agent nói chuyện với agent, còn AG-UI đưa agent vào ứng dụng có người dùng.

Cách hoạt động theo docs:

- Frontend POST một `RunAgentInput` gồm `threadId`, `runId`, `messages`, `tools`, `state`, `context`.
- Backend trả về luồng event. Mỗi run bắt buộc mở bằng `RUN_STARTED` và đóng bằng `RUN_FINISHED` hoặc `RUN_ERROR`.
- Text stream theo bộ ba `TEXT_MESSAGE_START`, `TEXT_MESSAGE_CONTENT` (mỗi event một `delta`), `TEXT_MESSAGE_END`, nối với nhau bằng `messageId`. Tool call có bộ `TOOL_CALL_START`, `TOOL_CALL_ARGS`, `TOOL_CALL_END`, `TOOL_CALL_RESULT`.
- State dùng chung giữa agent và UI đi theo kiểu `STATE_SNAPSHOT` (gửi toàn bộ) rồi `STATE_DELTA` (mảng JSON Patch theo RFC 6902).
- Transport không bị khóa: SSE, WebSocket, webhook. Bản tham chiếu dùng HTTP với `text/event-stream`.

README liệt kê integration first-party với Microsoft Agent Framework, Google ADK, AWS Strands Agents, Mastra, Pydantic AI, LlamaIndex, và community cho Claude Agent SDK. Repo ra release gần như mỗi ngày; bản 12/11 có thay đổi breaking: event text và tool call của adapter Claude SDK không còn mang `threadId`/`runId`, consumer phải đọc từ event cấp run.

Vì sao đáng chú ý: ai từng tự viết endpoint chat stream đều phải tự nghĩ format: gửi chunk text thế nào, báo "đang gọi tool" ra sao, lỗi giữa chừng thì báo gì. AG-UI là một bản thiết kế sẵn cho đúng câu hỏi đó, kể cả khi bạn không dùng SDK của nó.

Áp dụng: nếu đang có endpoint SSE cho chatbot trong FastAPI hay NestJS, đối chiếu format event hiện tại với danh sách event của AG-UI. Ít nhất hãy học hai ý: luôn có event mở và đóng run để frontend biết khi nào tắt loading, và tách snapshot với delta cho state.

Nguồn: [ag-ui-protocol/ag-ui](https://github.com/ag-ui-protocol/ag-ui), [AG-UI docs: Events](https://github.com/ag-ui-protocol/ag-ui/blob/main/docs/concepts/events.mdx), [AG-UI releases](https://github.com/ag-ui-protocol/ag-ui/releases)

### Vue 3.6.0-rc.15: hơn 15 fix cho reactivity, phần lớn quanh `computed`
RC thứ 15 của Vue 3.6 ra ngày 12/11, bản stable mới nhất vẫn là 3.5.45. Changelog dài, chia ba nhóm:

- **reactivity**: không còn mutate object options truyền vào `effect()`; không notify reader của một `computed` bị invalidate bởi chính lần chạy của nó; kết thúc dirty check khi các `computed` đọc lẫn nhau hoặc đọc chính mình; tiếp tục notify subscriber sau khi một `computed` throw, và tính lại reader khi nó hồi phục; giải phóng `computed` tạo ra trong lúc setup SSR.
- **runtime-vapor và compiler-vapor**: rất nhiều fix cho Vapor mode quanh KeepAlive, slot, Transition, hydration và HMR.
- **performance**: `compiler-sfc` bỏ bước liệt kê `include` của tsconfig; server renderer render compiled slot của element vnode ở push mode.

Vì sao đáng chú ý: các lỗi kiểu "computed throw một lần rồi UI không bao giờ cập nhật nữa" hay "computed tạo trong SSR không được giải phóng" là loại lỗi khó tái hiện trên production, nhất là với app Nuxt chạy SSR lâu ngày. Số lượng fix ở RC15 cho thấy hệ reactivity mới của 3.6 vẫn đang được mài.

Áp dụng: chưa nâng production. Nếu có project Vue nhỏ, thử cài bản RC ở branch riêng và chạy test, đặc biệt các chỗ có `computed` lồng nhau hoặc `computed` gọi API có thể throw.

Nguồn: [vuejs/core CHANGELOG (minor)](https://github.com/vuejs/core/blob/minor/CHANGELOG.md), [vuejs/core releases](https://github.com/vuejs/core/releases)

### Next.js 16.5 canary: Turbopack GC bật mặc định, `next dev` không còn chết im lặng
Hai thay đổi ở v16.5.0-canary.50 (14/11) đáng biết trước khi 16.5 ra:

- **Turbopack GC bật mặc định** (#101591). Option `experimental.turbopackGc` giờ là `true` cho cả dev và build khi bạn không cấu hình; đặt `false` để tắt. PR ghi rõ tính năng được nhắm cho 16.5. Cùng bản còn bật `turbopackMinifyBeforeChunking` mặc định trên canary.
- **`next dev` thoát có lỗi khi server con bị kill bằng signal** (#101752). Trước đây, nếu process server bị OOM killer bắn SIGKILL hoặc crash SIGSEGV, process cha thoát mà không log gì, có lúc vẫn chạy mà không có server, có lúc exit code 0. Giờ nó log tên signal và thoát với mã `128 + số signal`, ví dụ 137 cho SIGKILL, kèm gợi ý về bộ nhớ khi là SIGKILL.

Vì sao đáng chú ý: exit code 137 là con số bạn sẽ gặp lại trong Docker và Kubernetes, nghĩa là container bị kill do hết memory limit. Trước bản này, chạy `next dev` trong container RAM thấp có thể trông như bị treo mà không ai biết vì sao.

Áp dụng: nếu từng thấy `next dev` "đứng hình" trên VPS hay devcontainer nhỏ, khi lên 16.5 hãy xem exit code. Bản stable mới nhất vẫn là 16.4.6, đã nói ở bài 13/11.

Nguồn: [Next.js v16.5.0-canary.50](https://github.com/vercel/next.js/releases/tag/v16.5.0-canary.50), [PR #101591](https://github.com/vercel/next.js/pull/101591), [PR #101752](https://github.com/vercel/next.js/pull/101752)

## Cài đặt và dùng thử

### AG-UI: endpoint SSE bằng FastAPI với SDK Python
Lệnh cài từ README của SDK Python:

```bash
pip install ag-ui-protocol
```

Ví dụ tối thiểu ghép từ README SDK và quickstart server trong docs: encoder biến event thành dòng `data:` của SSE, field tự chuyển sang camelCase. Đoạn dưới chưa được chạy thử trong lần viết này; tên class đã đối chiếu với `ag_ui.core` trong source SDK.

```python
import uuid
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
from ag_ui.core import (
    RunAgentInput, EventType, RunStartedEvent, RunFinishedEvent,
    TextMessageStartEvent, TextMessageContentEvent, TextMessageEndEvent,
)
from ag_ui.encoder import EventEncoder

app = FastAPI()

@app.post("/")
async def agent(input_data: RunAgentInput, request: Request):
    encoder = EventEncoder(accept=request.headers.get("accept"))

    async def events():
        yield encoder.encode(RunStartedEvent(type=EventType.RUN_STARTED,
            thread_id=input_data.thread_id, run_id=input_data.run_id))
        mid = str(uuid.uuid4())
        yield encoder.encode(TextMessageStartEvent(type=EventType.TEXT_MESSAGE_START,
            message_id=mid, role="assistant"))
        yield encoder.encode(TextMessageContentEvent(type=EventType.TEXT_MESSAGE_CONTENT,
            message_id=mid, delta="Hello world!"))
        yield encoder.encode(TextMessageEndEvent(type=EventType.TEXT_MESSAGE_END,
            message_id=mid))
        yield encoder.encode(RunFinishedEvent(type=EventType.RUN_FINISHED,
            thread_id=input_data.thread_id, run_id=input_data.run_id))

    return StreamingResponse(events(), media_type="text/event-stream")
```

Gọi thử bằng lệnh `curl` trong quickstart:

```bash
curl -X POST http://localhost:8000/ \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"threadId":"thread_123","runId":"run_456","state":{},
       "messages":[{"id":"msg_1","role":"user","content":"Hello"}],
       "tools":[],"context":[],"forwardedProps":{}}'
```

Muốn có sẵn cả app mẫu, README đưa lệnh:

```bash
npx create-ag-ui-app my-agent-app
```

## Góc học sâu

### Streaming qua SSE với snapshot và delta
AG-UI là một ví dụ gọn của hai ý tưởng backend dùng ở rất nhiều nơi: stream event qua Server-Sent Events, và đồng bộ state bằng snapshot cộng delta.

**SSE là gì ở tầng HTTP.** Một response bình thường với `Content-Type: text/event-stream`, server không đóng kết nối mà ghi dần từng block `data: <json>` kết thúc bằng một dòng trống. Khác WebSocket, SSE chỉ một chiều server tới client, đi qua HTTP thường nên proxy, load balancer, auth header hoạt động như mọi request. Với chatbot thì đủ: client gửi một POST, server stream câu trả lời.

Ba lỗi hay gặp khi đưa SSE lên production:

1. **Reverse proxy buffer response.** Nginx mặc định buffer, client nhận cả đoạn một lúc ở cuối thay vì từng chunk. Tắt bằng `proxy_buffering off;` cho location đó, hoặc trả header `X-Accel-Buffering: no` từ app.
2. **Timeout giữa chừng.** Agent nghĩ lâu hoặc chờ tool thì kết nối im lặng vài chục giây, proxy hoặc load balancer cắt. Gửi heartbeat định kỳ (dòng comment `: ping`) hoặc tăng `proxy_read_timeout`.
3. **Không có event kết thúc rõ ràng.** Nếu stream chỉ "dừng", client không phân biệt được xong hay đứt mạng. Đây là lý do AG-UI bắt buộc mọi run phải kết thúc bằng `RUN_FINISHED` hoặc `RUN_ERROR`.

**Snapshot cộng delta.** Gửi toàn bộ state mỗi lần thay đổi thì tốn băng thông; chỉ gửi delta thì một delta bị mất là client lệch vĩnh viễn. Cách kết hợp: gửi snapshot đầy đủ lúc đầu và thỉnh thoảng, ở giữa gửi delta nhỏ. Client gặp snapshot thì thay hẳn state, gặp delta thì áp theo thứ tự. AG-UI dùng JSON Patch cho delta:

```json
[
  { "op": "replace", "path": "/order/status", "value": "paid" },
  { "op": "add", "path": "/order/items/-", "value": { "sku": "A1", "qty": 2 } }
]
```

Docs ghi rõ: nếu client phát hiện state không khớp sau khi áp patch, nó có thể xin lại snapshot. Đây cũng là nguyên lý của replication trong database (base backup cộng WAL trong PostgreSQL), của Redis replication (full sync bằng RDB rồi stream lệnh), và của event sourcing (snapshot định kỳ để không phải replay toàn bộ event). Khi thiết kế bất cứ thứ gì cần đồng bộ state liên tục, hỏi hai câu: delta mất thì phục hồi bằng gì, và bao lâu gửi lại snapshot một lần.

## AI hôm nay

### NVIDIA SkillEvaluator: đo xem một Agent Skill có giúp agent làm tốt hơn không
NVIDIA mở mã nguồn SkillEvaluator (Apache-2.0, đang trending), framework kiểm tra skill theo chuẩn Agent Skills qua ba tầng:

- **Tầng 1, validation**: skill có đúng cấu trúc, an toàn, tương thích harness không. Check tĩnh không cần LLM; khi thiếu, tool tự tải SkillSpector và Gitleaks để quét.
- **Tầng 2, deduplication**: phát hiện hướng dẫn lặp hoặc chồng chéo trong một skill hay giữa nhiều skill.
- **Tầng 3, live evaluation**: chạy task thật trong sandbox (mặc định Docker), so hành vi agent khi có và không có skill, có thể sinh dataset eval.

Dự án ghi rõ là experimental, hỗ trợ cộng đồng, không SLA. Tầng 3 tốn tiền model và cần Docker.

Áp dụng: team bắt đầu có thư mục skill dùng chung thì nên chạy tầng 1 trong CI như chạy lint, vì nó bắt được skill sai cấu trúc và secret bị commit nhầm vào skill. Lệnh từ README:

```bash
pip install skillevaluator
skillevaluator validate ./my-skill --tiers 1
```

Nguồn: [NVIDIA/SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator)

## Tối ưu dùng AI

### Chủ đề hôm nay: đóng gói quy trình của team thành Agent Skill, viết sao cho agent chọn đúng lúc

Nếu bạn thấy mình gõ đi gõ lại cùng một đoạn hướng dẫn cho agent ("tạo migration thì dùng lệnh này, đặt tên thế này, nhớ viết down"), đó là ứng viên cho một skill. Skill là một thư mục có file `SKILL.md` (frontmatter YAML cộng hướng dẫn), có thể kèm script và tài liệu tham khảo. Điểm khác CLAUDE.md: lúc khởi động agent chỉ nạp `name` và `description` của mọi skill; phần thân chỉ được đọc khi skill liên quan tới task. Chuẩn này đã được Anthropic chuyển cho Agentic AI Foundation từ 22/10, nên cùng một skill dùng được ở nhiều agent, như bộ stitch-skills ở trên.

Checklist rút từ tài liệu "Skill authoring best practices" của Claude:

1. **`description` quyết định skill có được dùng hay không.** Viết ở ngôi thứ ba, nói cả skill làm gì và khi nào dùng, chứa từ khóa người dùng hay gõ. Tối đa 1.024 ký tự. Tránh "Helps with database".
2. **`name`** tối đa 64 ký tự, chỉ chữ thường, số, gạch nối, không chứa `anthropic` hay `claude`. Docs gợi ý dạng gerund: `creating-migrations`, `reviewing-api-changes`.
3. **Ngắn.** Mặc định agent đã giỏi, chỉ viết điều nó chưa biết: quy ước riêng của team, lệnh cụ thể, cạm bẫy đã gặp. Thân `SKILL.md` dưới 500 dòng; dài hơn thì tách file.
4. **Progressive disclosure, tham chiếu chỉ một cấp.** `SKILL.md` là mục lục trỏ thẳng tới `reference/*.md`. Không để file A trỏ B trỏ C, vì agent có thể chỉ đọc một phần file lồng sâu.
5. **Chọn mức tự do theo độ rủi ro.** Review code: hướng dẫn dạng heuristic. Migration database: đưa đúng một lệnh và ghi "không sửa lệnh, không thêm flag".
6. **Việc tất định thì viết script.** Script chạy được mà không phải nạp nội dung vào context, chỉ output tốn token. Ghi rõ là "chạy" hay "đọc để tham khảo".
7. **Có vòng lặp kiểm chứng**: chạy validator, sửa, chạy lại, chỉ đi tiếp khi pass.
8. **Tên tool MCP phải đầy đủ** dạng `ServerName:tool_name`, nếu không agent có thể không tìm thấy tool khi có nhiều server.
9. **Viết eval trước.** Docs đề nghị ít nhất 3 kịch bản, đo agent khi chưa có skill, rồi viết vừa đủ để qua.

Template một skill tạo migration cho project NestJS dùng TypeORM, đặt ở `.claude/skills/creating-migrations/SKILL.md`:

```markdown
---
name: creating-migrations
description: Tạo và kiểm tra migration TypeORM cho PostgreSQL trong project này. Dùng khi người dùng yêu cầu thêm, sửa, xóa bảng hoặc cột, thêm index, hoặc nhắc tới migration, schema, database change.
---

# Tạo migration

## Quy trình
1. Sửa entity trong src/**/entities/ trước.
2. Chạy đúng lệnh, không thêm flag:
   npm run migration:generate -- src/migrations/<TenMoTa>
3. Mở file vừa sinh, kiểm tra hàm down() đảo ngược đủ mọi thay đổi của up().
4. Chạy: npm run migration:run rồi npm run migration:revert rồi npm run migration:run
5. Chỉ báo xong khi cả ba lệnh ở bước 4 đều thành công. Dán output.

## Quy tắc của team
- Thêm cột NOT NULL vào bảng có dữ liệu: thêm nullable trước, backfill, rồi mới đặt NOT NULL ở migration sau.
- Index trên bảng lớn: xem reference/large-tables.md.
- Không bao giờ sửa migration đã merge vào main; tạo migration mới.
```

Đặt các con số như "bảng lớn là bao nhiêu dòng" vào `reference/large-tables.md` thay vì nhồi vào `SKILL.md`. Sau đó nhờ một phiên agent mới (không có lịch sử chat) làm thử task "thêm cột phone vào users" và quan sát: nó có tự chọn skill không, có chạy bước revert không. Docs gọi đây là vòng Claude A viết skill, Claude B dùng thử, bạn quan sát rồi quay lại sửa.

Nguồn: [Claude Docs: Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [Anthropic: Donating Agent Skills to the Agentic AI Foundation](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)

### Áp dụng ngay hôm nay
Mở lịch sử chat với coding agent trong tuần qua, tìm một đoạn hướng dẫn bạn đã gõ lại từ hai lần trở lên. Biến nó thành một `SKILL.md` theo template trên, trong đó `description` có câu "Dùng khi...". Mở phiên agent mới, giao một task liên quan mà không nhắc tên skill, và xem agent có tự dùng nó không. Nếu không, sửa `description` trước, chưa cần sửa phần thân.
