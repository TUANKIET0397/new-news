# Tech Radar 09/11/2026: vercel-labs/agent-browser, proxy nén context billion-context và 2 ngày nữa là security release Node.js
> Hôm nay trending xoay quanh hạ tầng cho coding agent: một CLI điều khiển browser theo từng lệnh shell, một proxy nén context cho phiên làm việc dài, và một app self-hosted chạy nhóm agent. Ai đang dùng Claude Code hoặc Codex trên VPS nên đọc phần bảo mật của các tool này trước khi cài. Bản vá Node.js ngày 11/11 vẫn chưa ra.

## Điểm nóng hôm nay

### vercel-labs/agent-browser: browser cho agent, mỗi lần một lệnh shell
Repo (Rust, Apache-2.0) đang có khoảng 812 sao trong ngày trên GitHub Trending. Theo README, đây là CLI native để agent điều khiển browser: lệnh `snapshot` trả về trang dưới dạng text gọn, mỗi phần tử có một ref như `@e1`, agent hành động trên ref đó thay vì tự đoán selector. Bản tin 06/11 đã nhắc tên repo này; hôm nay mình đọc README kỹ hơn nên ghi thêm cách dùng.

Áp dụng: với backend/fullstack, đây là cách rẻ để agent tự kiểm chứng một trang đã deploy (form đăng nhập, flow thanh toán trên staging) mà không cần viết sẵn script Playwright. Vì agent đọc nội dung trang web, hãy coi mọi text trên trang là input không tin cậy (prompt injection), nhất là khi trang đó có nội dung do user tạo.

Nguồn: [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser)

### ranxianglei/billion-context: proxy nén context giữa agent và model API
README mô tả plugin chạy như một proxy nằm giữa agent và API của model, viết lại stream Anthropic/OpenAI. Nó tiêm thêm bốn tool (`compress`, `decompress`, `search_context`, `acp_status`) để model tự nén context khi dài ra; việc nén là từng phần, đảo ngược được và theo README thì giữ nguyên prefix cache. Tác giả nói tiết kiệm khoảng 5 lần token và đủ dùng với cửa sổ 100K. Đây là số liệu của tác giả, mình chưa kiểm chứng. README liệt kê hỗ trợ Claude Code, Codex, Gemini CLI, Aider, Copilot CLI và nhiều agent khác, mức độ tích hợp khác nhau.

Các giới hạn README tự nêu, đáng đọc trước khi dùng: proxy không có authentication, lịch sử ở phía client không nhỏ đi (chỉ phần gửi lên model bị nén), hội thoại dài chỉ chạy trên một instance vì các replica không chia sẻ state, và nhánh master có thể không ổn định. Trang cũng không nêu rõ license của phần code (chỉ ghi paper trong `paper/` là MIT), nên chưa thể dùng trong dự án có yêu cầu license.

Áp dụng: chỉ đáng thử khi bạn thật sự chạy phiên dài tốn token. Trước đó hãy dùng cách có sẵn ở phần "Tối ưu dùng AI" bên dưới, vì nó không cần thêm một proxy vào đường đi của API key.

Nguồn: [ranxianglei/billion-context](https://github.com/ranxianglei/billion-context)

### milind-soni/OpenMausBot: chat app self-hosted để chạy nhóm agent
Trending khoảng 1.437 sao trong ngày. Theo README, mỗi bot là một agent Claude hoặc Codex chạy local, có model, "computer" và app kết nối riêng. License Apache-2.0 (thư mục `enterprise/` có license riêng). Server chỉ bind `127.0.0.1`, lệnh shell và sửa file đi qua thẻ duyệt, nhưng API key lưu dạng plaintext trong `config.json` (quyền 0600 trên Unix). README không giải thích cách cô lập của Local VM, nên mình không đánh giá được độ an toàn của sandbox.

Áp dụng: xem như tài liệu tham khảo kiến trúc (permission broker, webhook chỉ mở vài endpoint) hơn là thứ cài ngay lên server chung.

Nguồn: [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot)

### Claude Code 2.1.319: vài thay đổi chưa nhắc hôm qua
Bản tin 08/11 đã nói về MCP task chạy nền và `permissions.denyInsteadOfPrompting`. Changelog chính thức của cùng bản còn ghi: lệnh `/claude-api latency-optimize` để tìm chỗ code gọi Claude API làm người dùng phải chờ và thử cài đặt nhanh hơn trên eval của bạn, biến `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` để ngừng tải feature flag mà không tắt telemetry, và `PostToolUse` hook giờ vẫn chạy (tối đa 10 giây) khi tool call kết thúc sau lúc một tin nhắn mới ngắt turn. Bản 2.1.318 (04/11) đổi để subagent chạy nền chuyển lệnh shell xuống nền sau 3 phút trên mọi provider, tránh prompt cache hết hạn trong lúc chờ.

Áp dụng: nếu backend của bạn gọi Claude API, thử `/claude-api latency-optimize` trên một endpoint chậm; kết quả cần được đối chiếu với eval của bạn trước khi đổi cấu hình.

## Cài đặt và dùng thử

### agent-browser
Theo README: có sẵn binary cho macOS, Linux (glibc và musl) và Windows; build từ source mới cần Node.js 24+, pnpm 11+ và Rust. Cài bằng npm không yêu cầu Node theo README.

```bash
npm install -g agent-browser
agent-browser install           # tải Chrome for Testing (chỉ lần đầu)
```

Trên Linux có thể cần thư viện hệ thống: `agent-browser install --with-deps`. Dùng thử không cần cài: `npx agent-browser open example.com`. Ví dụ tối thiểu:

```bash
agent-browser open example.com
agent-browser snapshot -i       # liệt kê phần tử tương tác kèm ref
agent-browser click @e1         # thao tác trên ref của snapshot
agent-browser get url           # kiểm tra kết quả
agent-browser close
```

### billion-context (chỉ khi thật sự cần)
Cài theo README, và chỉ chạy trên localhost vì proxy không có authentication:

```bash
npm install -g billion-context --prefix=~/.local
bili claude    # chạy Claude Code qua launcher
curl -s http://localhost:8787/__bili/health
```

## Góc học sâu

### State nằm ở đâu quyết định bạn scale thế nào
README của billion-context nói hội thoại dài chỉ chạy được trên một instance vì các replica không chia sẻ session state. Đây là mẫu quen thuộc của mọi service có state trong process: scale ngang chỉ hoạt động khi request nào cũng đến được nơi chứa state của nó.

Có ba cách xử lý:
- Sticky routing: load balancer đưa cùng một session về cùng instance (theo cookie hoặc header). Đơn giản, nhưng instance chết là mất state, và phân bổ tải lệch.
- Đẩy state ra ngoài: lưu session ở Redis hoặc PostgreSQL, instance trở thành stateless. Tốn thêm một lần round trip mỗi request và thêm một thành phần phải vận hành.
- Đặt state vào client rồi gửi lên mỗi lần: chỉ hợp khi state nhỏ và không nhạy cảm, hoặc được ký (JWT).

Quy tắc chọn: nếu mất state chỉ gây bất tiện (cache, tiến trình nén context), một instance kèm sticky là đủ. Nếu mất state là mất tiền hay mất dữ liệu, đẩy ra store có bền vững. Với app NestJS hay Laravel trên VPS, câu hỏi cần trả lời trước khi chạy hai container là: session, rate limit counter và file upload tạm đang nằm ở đâu?

## Tối ưu dùng AI

### Chủ đề hôm nay: context engineering, giữ context gọn bằng /clear, /compact có focus và đừng sửa lần thứ ba

Tài liệu best practices của Claude Code nói rõ các điểm sau:
- Các model hiện tại có cửa sổ 1M token và tự compact, nên hết context hiếm khi là vấn đề. Nhưng `/clear` giữa các task không liên quan vẫn đáng làm, vì context tập trung cho câu trả lời tốt hơn và rẻ hơn.
- `/compact` nên đi kèm focus, ví dụ `/compact keep the API changes and the test commands`. Trên phiên dài, bản thân `/compact` cũng là một request lớn vì nó đọc cả hội thoại để tóm tắt.
- Nếu bạn đã sửa cùng một lỗi hai lần mà agent vẫn sai, đừng sửa lần ba. Hội thoại đã chứa hai lần thử hỏng để agent đọc lại. Hãy `/clear`, rồi viết một prompt mới gói gọn những gì vừa học được.
- `/rewind` (hoặc nhấn `Esc` hai lần khi ô nhập trống) cho phép quay code và hội thoại về một prompt trước đó, nên thử hướng táo bạo trước rồi rewind nếu hỏng.

Quy trình áp dụng:
1. Xong một task (đã merge hoặc đã commit): `/clear` trước khi sang task khác.
2. Giữa task mà phiên đã dài: `/compact` kèm câu nói rõ cái cần giữ.
3. Agent sai lần thứ hai: dừng, `/clear`, viết lại prompt theo mẫu dưới.

```text
Bối cảnh: endpoint POST /orders trả 500 khi items rỗng (NestJS, file src/orders/orders.service.ts).
Đã thử và không hiệu quả: thêm try/catch ở controller (che lỗi, không sửa gốc).
Mong muốn: validate ở DTO, trả 400 với message rõ, thêm 1 test cho trường hợp items rỗng.
Kiểm chứng: chạy `npm test -- orders` và báo kết quả.
```

Nguồn: [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices)

### Áp dụng ngay hôm nay
Mở lại phiên agent dài nhất bạn đang giữ. Chạy `/clear`, rồi viết prompt khởi động lại theo mẫu trên cho việc đang làm dở (4 dòng: bối cảnh, đã thử, mong muốn, kiểm chứng). Mất khoảng 5 phút và bạn sẽ thấy phản hồi bám việc hơn.
