# Tech Radar 07/11/2026: V8 15.6 trong Node.js 27 alpha và Claude Code 2.1.319 vá lỗi bypass permission
> Hôm nay có hai tin kỹ thuật đáng đọc kỹ: bài ghi chú V8 của Node.js 27 alpha (serialization format mới, heap mặc định, GC pause ngắn hơn) và Claude Code 2.1.319 với nhiều bản sửa liên quan đến permission và sandbox. Ai chạy Node.js trên VPS hoặc Docker, và ai dùng coding agent trên repo thật, nên xem.

## Điểm nóng hôm nay

### Node.js công bố ghi chú V8 từ Node.js 26 lên 27 (V8 14.6 lên 15.6)
Ngày 05/11/2026 Node.js đăng bài về các thay đổi V8 trong bản 27 alpha. Bản alpha chưa dành cho production, nhưng bài này cho thấy trước những gì sẽ đổi khi 27 thành LTS. Phần đáng chú ý nhất với backend:
- Format serialization mới cho `v8.serialize()`, `structuredClone()` và `postMessage`. Node.js 26 trở xuống không đọc được dữ liệu do bản 27 ghi, sẽ báo lỗi "invalid or unsupported version". Bản mới đọc được dữ liệu cũ.
- Giới hạn old-generation mặc định lớn hơn trên máy 4 đến 15 GB RAM: một nửa bộ nhớ vật lý hoặc cgroup, chặn trong khoảng 256 MB đến 4 GB. Máy 8 GB giờ được 4 GB thay vì 2 GB. `Buffer` và `ArrayBuffer` cũng tính vào giới hạn toàn cục, nên thời điểm GC có thể đổi.
- Pause GC xấu nhất giảm từ khoảng 45 ms xuống khoảng 10 ms theo benchmark của V8. `JSON.parse` nhanh hơn với input nhiều string hoặc mảng object cùng shape, đọc property trên object có nhiều hoặc đã xóa property nhanh hơn khoảng 10 đến 20 phần trăm.
- `Array.prototype.sort()` dùng PowerSort thay TimSort cho mảng lớn. Kết quả vẫn stable, nhưng số lần gọi comparator và side effect trong comparator sẽ khác.
- Heap snapshot lớn hơn khoảng 2 lần và chứa toàn bộ source của script. Bài nhấn mạnh nên coi snapshot là dữ liệu nhạy cảm.
- Tính năng mới bật sẵn: `Math.sumPrecise()`, `Iterator.zip()`, `Iterator.prototype.join()`.

Áp dụng: nếu bạn cache object bằng `v8.serialize()` trong Redis và có giai đoạn rolling deploy chạy lẫn Node 26 và 27, instance cũ sẽ không đọc được entry do instance mới ghi. Hướng an toàn là serialize bằng JSON hoặc thêm version vào key cache. Với container có memory limit, đặt `--max-old-space-size` tường minh. Không commit hay upload heap snapshot lên chỗ chia sẻ.

Nguồn: [Notable V8 changes from Node.js 26 to 27 (Alpha)](https://nodejs.org/en/blog/announcements/notable-v8-changes-from-node-js-26-to-27-alpha)

### Claude Code 2.1.319: nhiều sửa lỗi permission, thêm MCP task chạy nền
Changelog chính thức của Claude Code có bản 2.1.319 (sau 2.1.318 đã đưa tin hôm qua). Các thay đổi liên quan đến công việc hằng ngày:
- MCP tasks hoạt động trong terminal: khi MCP server chạy tool call dạng task, Claude Code chuyển nó xuống background ngay và báo lại kết quả khi xong. Đặt `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` nếu muốn chờ trong chính tool call.
- Setting mới `permissions.denyInsteadOfPrompting`: tool call đang chờ permission prompt sẽ bị từ chối và turn tiếp tục, áp dụng cho terminal, subagent và teammate. Hữu ích cho chạy không giám sát.
- Biến môi trường `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` tắt việc tải feature flag mà không tắt telemetry.
- `claude -p` ở auto mode giờ thoát với mã 1 (trước là 0) khi hành động bị từ chối vì không có safety check. Script CI nên kiểm tra exit code.
- `/claude-api latency-optimize` giúp tìm chỗ code gọi Claude API làm người dùng phải chờ.

Áp dụng: nếu bạn dùng `claude -p` trong script hoặc CI, kiểm tra lại logic xử lý exit code sau khi nâng cấp. Nếu chạy agent không giám sát, cân nhắc `permissions.denyInsteadOfPrompting` để job không treo chờ prompt.

## Cài đặt và dùng thử

### Kiểm tra hành vi mới của Node.js 27 alpha với heap tường minh
Chỉ dùng để thử trên service nhỏ trong container riêng, không cho production. Binary tải từ trang dist của Node.js (có checksum và chữ ký). Cờ dưới đây là cờ có thật trong Node.js, dùng để đặt giới hạn heap thay vì dựa vào default mới:

```bash
node --max-old-space-size=2048 app.js
```

Sau đó so sánh RSS và thời gian GC với bản 26 trên cùng tải, và chạy test có dùng `v8.serialize()` để xem lỗi định dạng khi đọc chéo phiên bản.

## Góc học sâu

### Serialization format và tương thích phiên bản khi rolling deploy
Tin V8 hôm nay là ví dụ điển hình của vấn đề: dữ liệu ghi bởi version N+1 mà version N không đọc được. Trong hệ thống nhiều instance, deploy không bao giờ đổi tất cả instance cùng lúc, nên luôn có khoảng thời gian hai version cùng đọc và ghi vào cache, queue, hoặc database dùng chung.

Quy tắc thực tế:
- Backward compatible (bản mới đọc được dữ liệu cũ) thường dễ đạt. Forward compatible (bản cũ đọc được dữ liệu mới) mới là chỗ hay vỡ.
- Dùng format ổn định và có schema (JSON, Protobuf) cho dữ liệu sống lâu hơn một lần deploy. Format nội bộ của runtime như `v8.serialize()` phù hợp cho dữ liệu ngắn hạn trong cùng một version.
- Gắn version vào key cache (ví dụ `user:v2:123`) hoặc vào envelope của message để consumer biết cách đọc hoặc bỏ qua.
- Deploy theo hai bước khi đổi format: bước 1 cho code đọc được cả hai format, bước 2 mới bắt đầu ghi format mới.

## Tối ưu dùng AI

### Chủ đề hôm nay: viết CLAUDE.md ngắn, chỉ ghi những gì agent không tự tìm ra

Theo tài liệu best practices của Claude Code, `CLAUDE.md` được nạp vào mọi session nên mỗi dòng đều chiếm một chút sự chú ý của model ở mọi task. Phép thử trước khi viết một dòng:

1. Agent có tìm ra điều này bằng cách đọc code không?
2. Nó có thực sự đi tìm không?

Nếu cả hai đều có, bỏ dòng đó đi. Nên giữ: lệnh xác nhận công việc (test, typecheck, lint, cách chạy một file test), chỗ code gây hiểu nhầm (pattern cũ mà code mới không được copy), quyết định không nằm trong repo, và thứ bạn đã phải sửa hai lần. Ví dụ cho một repo NestJS, theo đúng khung của tài liệu:

```markdown
# Commands
- Install: pnpm install
- Run one test file: pnpm vitest run path/to/file.test.ts
- Typecheck: pnpm tsc --noEmit

# Conventions
- Dùng helper lỗi trong src/lib/errors.ts, không throw string thô
- src/legacy/ vẫn đang chạy nhưng không copy pattern của nó vào code mới

# Gotchas
- Integration test cần DATABASE_URL, xem .env.example
```

Một số điểm khác từ tài liệu:
- `/init` sinh bản đầu từ codebase, sau đó việc chính là xóa bớt dòng. Hướng dẫn memory khuyên giữ dưới 200 dòng.
- Quy tắc không có ngoại lệ (ví dụ không bao giờ sửa file client được generate) nên đặt vào hook thay vì CLAUDE.md. Thêm chữ IMPORTANT thường không giúp được nếu file đã dài.
- Quy tắc chỉ áp cho một phần codebase đặt trong `.claude/rules/` với `paths:` filter. Quy trình của team (release, runbook) đặt trong skill.
- Cho AGENTS.md hay file hướng dẫn của tool khác thì nguyên tắc ngắn và chỉ ghi điều không tự suy ra được vẫn đúng, nhưng tài liệu trên chỉ nói về CLAUDE.md.

Nguồn: [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices)

### Áp dụng ngay hôm nay
Mở CLAUDE.md của một repo bạn đang làm, đọc từng dòng và áp dụng hai câu hỏi ở trên. Xóa mọi dòng mà agent tự tìm ra được (cấu trúc thư mục, tên framework). Đảm bảo còn đủ ba lệnh: chạy một file test, typecheck, lint. Mất khoảng 15 phút, sau đó giao một task nhỏ và xem agent có tự chạy test không.
