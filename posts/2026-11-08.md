# Tech Radar 08/11/2026: Cloudflare mở skill audit bảo mật cho coding agent, Laravel 13.40 và V8 15.6 trong Node.js 27
> Cuối tuần này có ba thứ đáng đọc: Cloudflare công khai skill `security-audit` đang leo trending, Laravel 13.40.0 thêm hook theo dõi job chạy quá lâu, và Node.js đăng chi tiết các thay đổi V8 của bản 27 alpha. Ai chạy Node.js hoặc Laravel trên VPS và đang dùng coding agent nên xem qua. Bản vá bảo mật Node.js ngày 11/11 vẫn chưa ra.

## Điểm nóng hôm nay

### cloudflare/security-audit-skill: biến coding agent thành người audit bảo mật
Repo này đang đứng thứ hai trên GitHub Trending hôm nay (khoảng 2.088 sao trong ngày), license MIT. Theo README, đây là một skill cho coding agent chia việc audit thành sáu pha: reconnaissance, hunting theo vùng chưa được cover, validate candidate, xuất kết quả có cấu trúc, verify độc lập từng record, rồi làm báo cáo. Mỗi pha chạy bằng agent riêng biệt. README mô tả nó là hạt giống của harness tìm lỗ hổng mà Cloudflare dùng nội bộ.

Điểm đáng chú ý nằm ở yêu cầu: skill chỉ chạy build hoặc test của code đích khi có sandbox do OS cưỡng chế (chặn network ra ngoài, môi trường sạch, giới hạn tài nguyên, chỉ ghi vào thư mục scratch). Không có sandbox thì nó giữ các lead ở trạng thái `needs_validation` thay vì chạy code lạ. Đây là cách làm đúng, vì audit một repo không tin cậy bằng agent mà không cô lập thì chính agent là bề mặt tấn công.

Áp dụng: dùng cho repo cá nhân hoặc service nội bộ trước khi deploy lên VPS, đặc biệt các endpoint nhận input (upload, webhook, auth). Kết quả là gợi ý để bạn kiểm tra, không thay thế review của người. Đừng chạy trên repo không tin cậy ngoài container.

Nguồn: [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

### Node.js 27 alpha: V8 14.6 lên 15.6, những thay đổi chưa nằm trong release notes
Blog Node.js ngày 5/11 liệt kê các thay đổi V8 từ Node.js 26 sang 27 alpha (V8 14.6 lên 15.6). Ngoài những thứ bản tin trước đã nhắc (format serialize mới, heap limit mặc định), có thêm vài điểm dễ gây lỗi âm thầm:
- Một số hàm `Math` dùng libm của LLVM nên bit cuối của kết quả có thể khác (ví dụ `Math.log(3)`). Test hard-code số thực dấu phẩy động có thể fail.
- `Date.prototype.getTimezoneOffset()` không còn bị cắt về số phút nguyên, nên ngày lịch sử có thể trả giá trị lẻ.
- `error.stack` không còn tra lên prototype chain: `Object.create(err).stack` là `undefined`.
- Heap snapshot giờ chứa toàn bộ source của script, nặng gấp đôi và lớn gấp đôi. Hãy coi file snapshot là dữ liệu nhạy cảm.
- Bộ nhớ của `Buffer` và `ArrayBuffer` tính vào giới hạn cấp phát toàn cục của V8, nên thời điểm GC có thể đổi.
- `Array.prototype.sort()` dùng PowerSort cho mảng lớn. Kết quả vẫn stable, nhưng test đếm số lần gọi comparator sẽ khác.
- Tính năng mới bật mặc định: `Math.sumPrecise()`, `Iterator.zip()`, `Iterator.zipKeyed()`, `Iterator.prototype.join()`.

Áp dụng: khi thử 27 alpha trong container, chạy lại test suite và chú ý các test so sánh số thực chính xác tuyệt đối, đồng thời đừng gửi heap snapshot lên ticket công khai.

Nguồn: [Notable V8 changes from Node.js 26 to 27 (Alpha)](https://nodejs.org/en/blog/announcements/notable-v8-changes-from-node-js-26-to-27-alpha)

### Laravel 13.40.0: theo dõi job chạy lâu và reconnect trong transaction
Bản framework 13.40.0 ra ngày 3/11. Những thay đổi liên quan đến backend:
- `Queue::whenJobRunsLongerThan` và `Schedule::whenTaskRunsLongerThan` để chạy callback khi job hoặc task vượt ngưỡng thời gian.
- Helper middleware `$middleware->insertBefore()` và `insertAfter()`, `replace()` nhận mảng.
- Tự kết nối lại khi mất kết nối giữa chừng trong transaction.
- Sửa lỗi cập nhật JSON path trên MySQL/MariaDB và index qualification trên PostgreSQL.
- Làm chặt xử lý kết quả của `Concurrency` trước việc task output bị chèn nội dung.

Áp dụng: nếu bạn có queue worker trên VPS và đang tự viết đoạn log "job này chạy bao lâu", hook mới cho phép gom về một chỗ. Với bản 13.40.0 nên đọc kỹ phần reconnect trong transaction trước khi nâng cấp, vì hành vi retry giữa chừng cần được hiểu rõ với code có side effect ngoài DB.

## Góc học sâu

### Trace và long-running job: đo thời gian chạy là bước đầu của observability
Hook `whenJobRunsLongerThan` của Laravel và việc agent chạy nền của Claude Code cùng nói về một vấn đề: tác vụ dài mà không ai nhìn. Bản chất của observability cho job nền là có ba thứ: ngưỡng (bao lâu thì coi là bất thường), định danh (job nào, tham số nào) và hành động (log, alert, hủy). Thiếu ngưỡng thì mọi job chậm đều trông bình thường cho đến khi queue đầy.

Hai lưu ý khi áp dụng. Một, đặt ngưỡng theo phân vị (ví dụ p95 của job đó) thay vì một con số chung cho mọi job, vì job gửi email và job xuất báo cáo có thang thời gian khác nhau. Hai, tách "chạy lâu" khỏi "bị kẹt": job chạy lâu vẫn có tiến độ, job bị kẹt thì không. Cách rẻ nhất là cho job ghi heartbeat định kỳ (cập nhật timestamp vào Redis hoặc bảng DB) để alert dựa trên heartbeat im lặng, còn thời gian tổng chỉ dùng để thống kê. Cùng nguyên tắc với reconnect trong transaction: khi retry, hãy chắc job idempotent, nếu không việc tự chạy lại sẽ nhân đôi side effect.

### Claude Code 2.1.319: MCP task chạy nền, từ chối thay vì hỏi quyền
Changelog chính thức ghi bản 2.1.319 ngày 6/11/2026:
- Khi MCP server chạy tool call như một task, Claude Code đẩy nó xuống nền và báo kết quả khi xong. Đặt `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` để quay lại kiểu chờ trong tool call.
- Setting mới `permissions.denyInsteadOfPrompting`: tool call đáng lẽ chờ prompt quyền sẽ bị từ chối và turn tiếp tục, áp dụng cho cả subagent.
- `/loop` tự điều tiết nhịp giờ kết thúc khi một turn xong mà không đặt lịch lại. `CLAUDE_CODE_LOOP_KEEPALIVE=1` để giữ hành vi cũ.
- `/usage` hiện chi phí theo ngày, tuần, tháng cho người dùng đi qua Claude apps gateway.

Áp dụng: `denyInsteadOfPrompting` hợp với job chạy `claude -p` trong CI hoặc cron, nơi không có ai bấm duyệt, thay vì treo cả pipeline. MCP server của team (ví dụ gọi build hoặc migration dài) giờ không còn chặn session.

## Tối ưu dùng AI

### Chủ đề hôm nay: viết CLAUDE.md ngắn, và đẩy luật không có ngoại lệ sang hook
Tài liệu best practices của Claude Code nói rõ: `CLAUDE.md` được nạp vào mọi session nên mỗi dòng đều ăn một chút sự chú ý của model cho mọi task, kể cả task không liên quan. Vì vậy file chỉ nên giữ những gì model không tự suy ra được từ code:
- Lệnh xác nhận công việc: test, typecheck, lint, cách chạy một file test.
- Chỗ code gây hiểu lầm: pattern cũ còn khắp nơi nhưng code mới không được bắt chước, thư mục trông như không dùng nhưng đang chạy.
- Quyết định không nằm trong repo: dùng error helper nào, deploy ra sao, cái gì cần review migration.
- Bất cứ thứ gì bạn đã phải sửa hai lần.

Template cho một dự án NestJS (điền theo repo của bạn):

```markdown
# Commands
- Install: pnpm install
- Run one test file: pnpm jest path/to/file.spec.ts
- Typecheck: pnpm tsc --noEmit

# Conventions
- Dùng exception filter trong src/common/filters, không throw string thô
- src/legacy/ vẫn đang chạy nhưng đừng bắt chước pattern ở đó

# Gotchas
- Integration test cần DATABASE_URL, xem .env.example
```

Quy trình từng bước:
1. Chạy `/init` để có bản nháp, sau đó việc chính là xóa dòng. Memory guide của Claude Code khuyến nghị giữ dưới 200 dòng.
2. Xóa mọi thứ model đọc repo là biết: mô tả cấu trúc thư mục, quy ước đặt tên đã thể hiện trong code.
3. Chạy `/doctor` để nó gợi ý phần cắt, và `/doctor prompt-audit` để tìm dòng cũ, file không còn tồn tại hoặc dòng mâu thuẫn nhau.
4. Chạy `/context all` để xác nhận file đã được nạp.
5. Sở thích cá nhân đặt trong `CLAUDE.local.md` và thêm vào `.gitignore`.

Phần quan trọng nhất là phân biệt guideline và luật cứng. Theo tài liệu, một dòng như `Never read .env` hay `Don't touch the migrations folder` được model làm theo gần như luôn luôn, nhưng "gần như" chưa phải chắc chắn. Nếu bạn cứ thêm IMPORTANT mà model vẫn bỏ sót, đó là dấu hiệu dòng đó nên là hook. Ví dụ hook chạy Prettier sau mỗi lần sửa file (lấy từ tài liệu):

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write --ignore-unknown \"$(jq -r '.tool_input.file_path')\"" }
        ]
      }
    ]
  }
}
```

Luật migration thì dùng `PreToolUse` hook thoát với exit code 2 cho đường dẫn dưới `migrations/`; bạn có thể nhờ Claude viết giúp bằng prompt `write a hook that blocks edits to the migrations folder`. Đừng lạm dụng: hook dành cho luật không có ngoại lệ, còn kiểu `Prefer named exports` có nhiều ngoại lệ nên giữ trong CLAUDE.md. Quy trình dài như checklist release nên là skill, vì skill chỉ nạp nội dung đầy đủ khi task cần.

### Áp dụng ngay hôm nay
Mở CLAUDE.md của một dự án đang làm và đếm số dòng. Trong 15 phút: xóa mọi dòng mà người mới đọc repo cũng tự biết, chắc chắn còn lệnh chạy một file test và lệnh typecheck, rồi tìm một luật bạn từng nhắc agent hai lần (ví dụ không sửa `migrations/`) và chuyển nó thành `PreToolUse` hook. Thử bằng cách bảo agent sửa một file trong thư mục đó và xem hook có chặn không.
