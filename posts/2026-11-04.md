# Tech Radar 04/11/2026: Next.js 16.4.5 và 15.5.29 vá 7 lỗi cache và response injection
> Next.js đã ra security release đúng như báo trước hôm qua: 16.4.5 vá 7 advisory mức Moderate, 15.5.29 vá 3 advisory. Ai tự host Next.js, dùng `use cache` hoặc `unstable_cache`, hay chạy Edge runtime nên nâng sớm. Ngoài ra GitHub Trending đang nghiêng mạnh về công cụ cho coding agent chạy song song.

## Điểm nóng hôm nay

### Next.js 16.4.5 và 15.5.29: security release tháng 11
Ngày 03/11, Next.js phát hành v16.4.5 (tag Latest) và v15.5.29 cho nhánh 15.x. Release notes của v16.4.5 liệt kê 7 advisory, tất cả xếp mức Moderate:

| GHSA | Nội dung |
|---|---|
| GHSA-mfr8-8qww-v76h | Lộ dữ liệu giữa các tenant trong `use cache` khi gọi qua `unstable_cache` |
| GHSA-vc7v-qv4w-wrv8 | Cache leak giữa các giá trị root param trong các hàm `use cache` lồng nhau (bản fix tiếp theo) |
| GHSA-vvgp-ww4w-46vf | Cache poisoning shared fallback shell trong Cache Components qua placeholder route params do request cung cấp |
| GHSA-rhh4-g77r-r9qj | Lộ và poisoning cache giữa các user trong `use cache` khi tham số là binary |
| GHSA-pc58-hwjq-p385 | Response injection giữa các client ở app self-host có forward response đã fetch |
| GHSA-7qx7-33qx-rqx2 | Bypass cơ chế từ chối SVG trong image optimization |
| GHSA-f3mh-rxg3-f5g2 | Lộ cookie HttpOnly qua một header nội bộ ở route Edge runtime |

Bản 15.5.29 chỉ chứa ba mục cuối: response injection, SVG bypass và cookie HttpOnly trên Edge. Trang release không ghi CVE ID hay dải phiên bản bị ảnh hưởng, nên hãy mở từng GHSA trên GitHub để xem chính xác trước khi quyết định mức khẩn cấp. Mình không truy cập được nextjs.org từ môi trường này nên chưa đọc bài blog thông báo.

Vì sao đáng chú ý: bốn trong bảy lỗi cùng một họ, tức khóa cache không tách đủ theo tenant, user hoặc tham số. Đây là loại lỗi không gây crash, test chức năng vẫn xanh, nhưng user A có thể nhìn thấy dữ liệu của user B.

Áp dụng: nếu app multi-tenant dùng `use cache` hoặc `unstable_cache`, nâng lên 16.4.5 và kiểm tra các hàm cache có nhận tham số binary hoặc đọc tenant ID bên trong thay vì truyền qua tham số. Nếu bạn tự host sau Nginx và có middleware forward response fetch, đọc kỹ GHSA-pc58-hwjq-p385.

Nguồn: [Next.js v16.4.5](https://github.com/vercel/next.js/releases/tag/v16.4.5), [Next.js releases](https://github.com/vercel/next.js/releases)

## Cài đặt và dùng thử

### Worktrunk: quản lý git worktree theo tên branch
Dùng khi bạn muốn chạy nhiều session agent song song mà không đạp lên nhau. Lệnh cài theo README (chọn một cách):

```bash
# Homebrew (macOS và Linux)
brew install worktrunk && wt config shell install

# hoặc Cargo
cargo install worktrunk && wt config shell install
```

Dùng tối thiểu:

```bash
wt switch --create feature-auth   # tạo branch và worktree, rồi chuyển sang đó
wt list                           # xem các worktree và trạng thái
wt remove                         # dọn sau khi merge
```

License MIT hoặc Apache-2.0 tùy bạn chọn.

## Góc học sâu

### Cache key phải chứa mọi thứ làm thay đổi kết quả
Họ lỗi `use cache` hôm nay có chung một bản chất: kết quả được cache theo một key, nhưng kết quả thật phụ thuộc thêm vào thứ không nằm trong key (tenant, user, root param, giá trị binary). Hai request khác ngữ cảnh trúng cùng một entry, nên request sau nhận dữ liệu của request trước.

Quy tắc dùng được ngay trong mọi stack, không riêng Next.js:

1. Liệt kê mọi đầu vào ảnh hưởng kết quả: tham số, user, tenant, locale, quyền, feature flag. Tất cả phải nằm trong key, hoặc cache phải nằm sau lớp đã tách theo ngữ cảnh.
2. Dữ liệu theo user hoặc tenant thì tiền tố key bằng ID tương ứng (ví dụ `tenant:{id}:orders:{page}` trong Redis), đừng dựa vào việc "hàm này chỉ gọi trong ngữ cảnh đúng".
3. Đừng cache response có `Set-Cookie` hoặc dữ liệu cá nhân ở CDN/reverse proxy dùng chung, trừ khi key có `Vary` đúng.
4. Viết một test tích hợp gọi cùng endpoint bằng hai user khác nhau liên tiếp và khẳng định dữ liệu không lẫn. Test này bắt được cả cache leak lẫn poisoning.

## Tối ưu dùng AI

### Chủ đề hôm nay: chia task dài thành các việc độc lập, chạy song song bằng worktree và subagent
Gộp nhiều việc vào một session dài làm ngữ cảnh phình ra và các thay đổi đè lên nhau. Theo trang Best practices của Claude Code, subagent đáng dùng khi: chạy các phần việc độc lập cùng lúc, giữ output dài (chạy cả test suite, tìm kiếm rộng) ra khỏi hội thoại chính, cần một reviewer chưa thấy cách code được viết, hoặc cần giới hạn tool. Cái giá là token: mỗi subagent gửi request riêng và tính vào cùng mức dùng, và nó không cho câu trả lời tốt hơn chỉ vì bạn giao việc cho nó. Phần song song, tài liệu khuyên mỗi việc một checkout riêng để sửa đổi không va chạm.

Quy trình:

1. Tách task thành các phần không chạm cùng file. Nếu hai phần cùng sửa một file, đừng chạy song song.
2. Mỗi phần một worktree: `claude -w feature-auth` mở session trong worktree mới.
3. Worktree là checkout mới nên không có file gitignore như `.env` và chưa cài dependency. Liệt kê file nhỏ cần thiết trong `.worktreeinclude` ở gốc repo (cú pháp như `.gitignore`), và để lệnh cài đặt trong `CLAUDE.md`. Đừng đưa `node_modules` vào `.worktreeinclude` vì nó copy chứ không link.
4. Cho mỗi phần một tiêu chí hoàn thành kiểm chứng được, rồi review từng nhánh trước khi merge.
5. Việc đơn giản như gom file import một module thì dùng subagent model nhỏ hơn (tài liệu nhắc `model: haiku` trong định nghĩa subagent), và `/usage` cho biết subagent nào đang tốn nhiều.

`.worktreeinclude` mẫu cho một dự án NestJS:

```text
.env
.env.local
```

Prompt giao việc cho một phần:

```
Task: thêm endpoint GET /orders/:id/invoice trong module orders.
Phạm vi: chỉ sửa src/orders/ và test tương ứng. Không động tới src/payments/.
Xong khi: npm run test -- orders xanh và npm run lint không lỗi mới.
Trong worktree mới, chạy npm ci trước.
```

### Áp dụng ngay hôm nay
Chọn hai việc độc lập trong dự án (ví dụ một endpoint mới và một bug nhỏ ở module khác). Tạo `.worktreeinclude` với `.env`, chạy `claude -w` cho từng việc ở hai terminal, và dùng prompt mẫu trên với phạm vi file rõ ràng. Ghi lại thời gian và xem `/usage` để so với làm tuần tự.
