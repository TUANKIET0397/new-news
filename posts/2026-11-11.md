# Tech Radar 11/11/2026: hôm nay là ngày Node.js vá lỗi High, agent-skills của Addy Osmani và Topcoat của tokio-rs lên trending
> Ngày Node.js hứa phát hành bản vá bảo mật mức High cho 22.x, 24.x và 26.x là hôm nay, nhưng tại thời điểm viết bài bản vá chưa xuất hiện trên GitHub releases. Trending có hai thứ đáng xem: bộ skill kỹ sư cho coding agent của Addy Osmani và Topcoat, framework full-stack Rust của nhóm tokio. Ai chạy Node.js production nên để sẵn pipeline redeploy, ai gọi Claude API nên đọc phần structured output.

### tokio-rs/topcoat: framework web full-stack bằng Rust, render ở server
README mô tả Topcoat là framework Rust "batteries-included": toàn bộ markup render ở server, component có thể async và query database trực tiếp. Phần reactivity dùng biểu thức `$(...)` viết bằng Rust có kiểm tra kiểu, được tính ở server cho lần render đầu và dịch sang JavaScript để cập nhật trên trình duyệt, không cần bundle wasm. Component đánh dấu `#[shard]` sẽ render lại ở server khi tham số đổi và HTML được thay tại chỗ. Có routing theo module, UI component kiểu shadcn/ui dùng Tailwind, cookie, session, mail, OpenAPI, và tích hợp htmx, Alpine AJAX, Datastar. Khoảng 6.800 sao, MIT.

Vì sao đáng chú ý: mô hình server-driven UI (giống Laravel Livewire hay Phoenix LiveView) đang quay lại, và đây là bản của hệ sinh thái tokio. README ghi rõ dự án còn sớm, thử nghiệm, "Expect breaking changes"; auth và background job vẫn nằm trong roadmap. Áp dụng: chưa dùng cho production, nhưng đáng đọc để so sánh cách tiếp cận với Next.js Server Components.

Nguồn: [tokio-rs/topcoat](https://github.com/tokio-rs/topcoat), [Topcoat getting started](https://github.com/tokio-rs/topcoat/blob/main/docs/getting_started.md)

## Góc học sâu

### Vá runtime mà không downtime: graceful shutdown và rolling restart
Khi cần đổi phiên bản Node.js trên VPS hay Docker, rủi ro không nằm ở lệnh build mà ở lúc thay process cũ bằng process mới. Nếu container cũ bị kill giữa chừng, request đang xử lý bị cắt, transaction có thể dang dở, job trong queue bị nhận mà không ack.

Bản chất của rolling restart an toàn gồm ba phần:
1. **Readiness tách khỏi liveness**: process mới chỉ nhận traffic khi endpoint readiness báo sẵn sàng (đã kết nối DB, Redis). Liveness chỉ trả lời "process còn sống".
2. **Graceful shutdown**: khi nhận `SIGTERM`, process ngừng nhận kết nối mới, báo readiness là không sẵn sàng, chờ request đang chạy xong trong một khoảng timeout, đóng pool DB rồi mới thoát. Trong NestJS là `app.enableShutdownHooks()` kết hợp lifecycle hook `onApplicationShutdown`; trong Node thuần là `server.close()`.
3. **Thay từng phần**: load balancer (nginx, Traefik, hoặc orchestrator) chuyển traffic sang instance mới trước, rồi mới gửi `SIGTERM` cho instance cũ.

Một lỗi hay gặp với Docker: process Node không phải PID 1 đúng nghĩa (bị bọc bởi `npm start` hay shell script), nên `SIGTERM` không tới được app và container bị kill cứng sau thời gian chờ. Cách kiểm tra nhanh: chạy `docker stop` với container của bạn và xem log có dòng shutdown của app hay không. Với worker queue, dừng nhận job mới trước, xử lý xong job hiện tại, và đảm bảo job có thể chạy lại an toàn (idempotent) nếu bị cắt.

## Tối ưu dùng AI

### Chủ đề hôm nay: structured output và JSON schema khi gọi API từ backend

Khi backend cần dữ liệu có cấu trúc từ LLM (trích xuất thông tin từ email, phân loại ticket, tạo payload cho API khác), đừng dựa vào câu "hãy trả về JSON" trong prompt rồi `JSON.parse` và cầu may. Claude API có structured outputs: bạn đưa JSON schema vào `output_config.format` với `type: "json_schema"`, response sẽ khớp schema. Với tool use thì đặt `strict: true` trên tool để đảm bảo tên tool và input đúng schema. Theo docs, tham số cũ `output_format` đã deprecated và chuyển sang `output_config.format`, không cần beta header nữa.

Ví dụ TypeScript từ docs chính thức:

```ts
import Anthropic from "@anthropic-ai/sdk";
import { jsonSchemaOutputFormat } from "@anthropic-ai/sdk/helpers/json-schema";

const client = new Anthropic();

const response = await client.messages.parse({
  model: "claude-opus-5-5",
  max_tokens: 1024,
  messages: [
    {
      role: "user",
      content: "Extract contact info: John Smith, john@example.com, interested in the Pro plan"
    }
  ],
  output_config: {
    format: jsonSchemaOutputFormat({
      type: "object",
      properties: {
        name: { type: "string" },
        email: { type: "string" },
        planInterest: { type: "string" }
      },
      required: ["name", "email", "planInterest"],
      additionalProperties: false
    } as const)
  }
});

console.log(response.parsed_output);
```

Checklist khi thiết kế schema, rút từ phần giới hạn trong docs:
1. Luôn đặt `additionalProperties: false` cho object; giá trị khác bị từ chối.
2. Không dùng được ràng buộc số (`minimum`, `maximum`), ràng buộc độ dài chuỗi (`minLength`, `maxLength`), schema đệ quy và `$ref` ra ngoài. Dùng sai sẽ nhận lỗi 400. Những ràng buộc này hãy kiểm tra lại ở tầng validation của bạn (class-validator, Zod, Pydantic, Laravel validation).
3. Dùng `enum` cho trường phân loại, nhưng so sánh không phân biệt hoa thường vì docs ghi model có thể đổi cách viết hoa của giá trị `enum`.
4. Kiểm tra `stop_reason` trước khi dùng kết quả: `refusal` có thể cho output không khớp schema, `max_tokens` nghĩa là output có thể bị cắt, cần tăng `max_tokens` rồi thử lại.
5. Giữ schema trong code như một hằng số dùng chung giữa phần gọi API và phần validate, đừng viết hai nơi.

Lưu ý: structured output đảm bảo hình dạng, không đảm bảo nội dung đúng. Một email bịa vẫn hợp lệ với `"type": "string"`. Validation nghiệp vụ vẫn là việc của backend.

Nguồn: [Structured outputs (Claude docs)](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)

### Áp dụng ngay hôm nay
Tìm một chỗ trong code đang `JSON.parse` output của LLM (hoặc dùng regex để móc JSON ra khỏi text). Viết JSON schema cho nó với `additionalProperties: false`, chuyển sang `output_config.format`, và thêm một nhánh xử lý khi `stop_reason` là `refusal` hoặc `max_tokens`. 15 phút là đủ cho một endpoint.
